# K3UI Expressive — audit & patch (novembre 2026)

Périmètre : dépôt complet à `03b7b68` (core, bootstrap, registre, thème, lifecycle, 79 composants,
motion, lazy, sanitizer, dépendances, tests, CI, build). Chaque constat ci-dessous a été vérifié
dans le code et, quand c'était possible, reproduit (Vitest/jsdom ou Chromium via Playwright).
Les constats non reproduits sont marqués comme tels.

## 1. Architecture constatée

| Couche | Fichiers | État |
| --- | --- | --- |
| Entrée | `src/index.ts` | Ré-exporte l'API, crée `window.K3UI`, lance `autoBootstrap()` sauf `K3UI_MANUAL`. |
| Bootstrap | `src/bootstrap/init.ts` | Locale → thème → `registry.registerAll()` → haptique → garde ligatures → gestures. |
| Registre | `src/registry/{catalog,deps,register}.ts` | Catalogue de `import()` + graphe de dépendances testé (`registry-deps.test.ts`). Enregistrement paresseux, mais **bundle unique** (`inlineDynamicImports: true`) : pas de lazy-loading JS réel. |
| Base | `src/core/k3-element.ts`, `lifecycle.ts` | `emit()` = `bubbles + composed`, `cancelable` opt-in ; lifecycle `k3-*-start` annulable. Conventions homogènes (vérifié : aucun `CustomEvent` DOM hors de ces helpers sans `composed`). |
| Thème | `src/theme/apply.ts` | MCU 0.4, specs 2021/2025, 8 variantes, contraste, `auto` horaire / `system` OS. |
| Motion | `src/motion/*`, tokens `_motion.scss` | CSS transitions + WAAPI + `waitForMotion`. `prefers-reduced-motion` et `data-k3-reduce-motion` neutralisent les durées via tokens. |
| Lazy | `src/core/lazy.ts`, `<k3-lazy>` | `whenTriggered` (IO/idle/interaction) avec `AbortSignal` ; `<k3-lazy>` annule à la déconnexion. Correct. |
| Sanitizer | `src/core/sanitize.ts` | Allowlist, parsing inerte, reconstruction nœud par nœud, limites. Bien testé (mXSS, clobbering, URL). **Non modifié.** |
| Tests / CI | Vitest (109 fichiers), 1 spec Playwright, CI : lint/test/build | e2e absent de la CI. |

### Vérifié sans défaut (non modifié)

- `sanitizeHTML` : parsing inerte, pas d'`innerHTML`, allowlists, schémas d'URL avec bruit de contrôle, `noopener`, limites — suite de tests existante solide (mXSS, clobbering, entités).
- `k3-qr-code` : SVG construit avec `escapeXml`, `safeColor`, `safeHref`.
- `k3-codeblock` : sortie du tokenizer échappée (`escapeHtml`) avant `unsafeHTML`.
- `<k3-lazy>` / `whenTriggered` : `AbortController` à la déconnexion, nettoyage des observateurs.
- Observateurs / timers : 26 fichiers créent des observateurs ou intervalles ; chacun a un chemin de nettoyage (`disconnect` / `clearInterval`) — revue par comptage, pas test par test — sauf la garde de ligatures (C3).
- Événements : `bubbles + composed` systématiques, `cancelable` sur les phases `*-start`.

## 6. Compatibilité

Aucune API publique supprimée ou renommée, aucun événement renommé, aucun export retiré.
Changements de comportement assumés (corrections) :

- Tab ne quitte plus un dialog / une feuille modale ; le focus entre dans le panneau à l'ouverture.
- Une seule couche se ferme par Escape.
- `k3-tabs` : un seul arrêt de tabulation (flèches entre onglets) — motif APG.
- `k3-text-field` / `k3-select` `required` bloquent désormais la soumission native.
- `K3UI.init()` sans `components` lors d'un re-init n'enregistre rien de plus (déjà fait au premier appel).
- SVG d'icônes de `k3-tabs` : `style`, `href`, `<use>`, `<image>` sont retirés.
- `themeApi.apply()` identique ignoré (pas de second `k3-theme-change` pour la même signature).

## 7. Limites restantes et recommandations (prochain patch)

1. **Bundle unique** — `inlineDynamicImports` + ré-exports statiques (`ChartJs`, `K3AudioPlayer`, QR, halftone…) depuis `src/index.ts` : Chart.js (≈257 kB bruts), le lecteur audio (≈99 kB) et le QR (≈63 kB) sont toujours chargés. Proposition : conserver `dist/k3ui.js` tel quel et **ajouter** une sortie `dist/esm/` (`preserveModules`) + des points d'entrée par composant (`k3ui/components/chart`), le catalogue pointant vers ces chunks. Non fait ici : changement de packaging à valider (CDN « 1 JS + 1 CSS » documenté).
2. **ResizeObserver** : un par instance dans 17 fichiers (16 composants + `core/surface-variant`). Un observateur partagé (même principe que `core/visibility.ts`) est la suite logique ; migration composant par composant avec tests.
3. **Locale** : chaque `K3Element` ajoute un écouteur `k3-locale-change` sur `document`. Un registre partagé (Set + un seul écouteur) réduirait le coût à grande échelle.
4. **`:host-context([data-k3-reduce-motion])`** (42 occurrences) n'est pas supporté par Firefox/Safari ; les tokens de durée couvrent l'essentiel, mais les règles spécifiques ne s'appliquent qu'à Chromium. Préférer une variable CSS héritée.
5. **Moteur de motion centralisé** : non implémenté volontairement — les animations reposent sur CSS/WAAPI (compositor) et `waitForMotion` ; un moteur JS (priorités, springs) dupliquerait cela et ajouterait du coût. Le signal de visibilité partagé couvre « hors écran / onglet masqué ».
6. **Overlay manager étendu** : menus, select, date/time pickers et tooltips ne sont pas dans la pile (ils gèrent Escape en consommant l'événement). Le top layer (`popover`) n'est utilisé que par tooltip et time-picker.
7. **Configuration** non ajoutée faute de mécanisme sous-jacent : densité globale, formes, typographie / `textScale`, transparence. Elles demandent d'abord des tokens CSS dédiés.
8. **À vérifier** : retrait de l'attribut `open` d'un dialog visible (sans `hide()`) — non testé.
9. **Firefox / WebKit** : exécuter `K3UI_E2E_ALL_BROWSERS=1 npm run test:e2e` puis rendre le job CI bloquant.
